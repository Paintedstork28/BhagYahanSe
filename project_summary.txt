# BhagYahanSe (aka BhagBenStokes) — Project Summary

## Project Concept
A Chrome extension + AI chatbot that tracks India's medal performance at the Asian Games in real time. Built out of irritation — switching between SonyLIV, Olympics.com, and news sites mid-workday wasn't cutting it. The extension sits in your browser toolbar with a live medal banner, badge notifications for new medals, and a conversational AI agent that answers questions about athletes, events, and medal counts.

Target user: Anyone following Indian athletes at multi-sport events.

---

## How It Was Built

### Architecture
```
User (Chrome Extension / Chatbot)
    ↓ HTTP requests
Flask API Server (server.py)
    ↓ routes to
LangGraph Agent (LangChain + OpenRouter/Gemini)
    ↓ decides
Tool calls (scrape, lookup, filter)
    ↓ returns
Structured data → LLM formats response → User
```

### Framework Journey
1. **Google ADK + Gemini** — started here, hit rate limits and model retirement
2. **LangChain + OpenRouter** — switched for model interoperability (ADK doesn't support OpenRouter)
3. **Flask API** — wrapped the agent for Chrome extension access
4. **Chrome Extension** — popup UI with medal banner, chatbot, and background polling

### Key Technical Decisions
- **Code-level guardrails over prompts**: Telling the LLM "only Indian athletes" didn't work — it discussed Usain Bolt. Nationality check enforced in Python code.
- **Multi-source scraping with pre-facto dedup**: DuckDuckGo news (fast) + Wikipedia (reliable, has dates/sport labels) + IOA official site (cross-check). Each medal normalized before adding.
- **5-tuple dedup key**: `(sport, medal_type, gender, event_key, entry_type)` with sport canonicalization, fuzzy matching, and team name normalization
- **IOA tally gate**: Our G/S/B counts validated against official IOA numbers — our count must never exceed IOA
- **Date-aware queries**: Wikipedia dates backfilled onto news entries, normalized to ISO format, all in JST (UTC+9) for Nagoya timezone
- **15-minute polling**: Extension checks for new medals every 15 minutes during active competition

## Data Sources
- **Wikipedia** — athlete profiles, medal tables with dates and sport labels (free, no key)
- **DuckDuckGo News** — fast medal discovery from news articles (free, no key)
- **IOA (olympic.ind.in)** — official Indian medal tally for cross-checking (free, no key)
- **OpenRouter API** — LLM access to free models (free tier, API key required)
- **Google Gemini API** — backup LLM (free tier, API key required)

## APIs & Costs
- OpenRouter API — free tier
- Google Gemini API — free tier
- Wikipedia / DuckDuckGo / IOA — no API key needed
- Total monthly cost: **$0**

## Data Refresh
- Extension polls every **15 minutes** during active competition
- Every **6 hours** during idle (checks if a competition is active)
- Medal data scraped fresh on each poll (not cached server-side)
- IOA tally checked on every poll for validation

## Key Dedup Fixes (Phase 13-14)
Problems solved:
- "MMA" vs "Mixed martial arts" → sport canonicalization map
- "Indian women's cricket team" vs "India women's national cricket team" → team name normalization
- "+90 kg" vs "90+kg" → weight class regex normalization
- "Joshna Chinappa and Velavan" vs "Velavan, Joshna" → "and" detection + doubles/pair event check
- "Marathon" as separate sport vs under "Athletics" → sport alias mapping
- 85 scraped medals → 60 actual (5 rounds of dedup iteration)
- IOA tally gate validates our counts never exceed official numbers
